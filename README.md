# SS14 Prototype Builder

Настольное приложение для Space Station 14: собирает YAML-прототипы через формы и
генерирует `meta.json` для папок со спрайтами (`.rsi`). Без внешних зависимостей —
только Python 3.8+ с tkinter.

## Запуск

```
python main.py
```

* **Windows / macOS** — tkinter входит в стандартный установщик Python с python.org.
* **Linux** — при необходимости: `sudo apt install python3-tk`.

## Что умеет

### Вкладка «Прототип»
1. Выберите **тип прототипа** (entity, gas, reagent, Tag, damageType, damageGroup, stack,
   soundCollection, latheRecipe или свой).
2. Заполните основные поля: ID, название, описание и т.д. (поле со звёздочкой обязательно,
   `(?)` — наведите курсор, чтобы увидеть подсказку и пример).
3. Для `entity` добавляйте **компоненты**: слева список по категориям («Визуальные эффекты»,
   «Урон и броня», «Триггеры и взрывы» …) с поиском; двойной клик или «Добавить →» открывает окно
   со всеми параметрами компонента (для `Sprite` — RSI, state, цвет, масштаб, слои и т.д.).
   Добавленные компоненты можно изменить, убрать и переставить.
4. Справа виден готовый YAML (обновляется на лету). «Копировать YAML» или
   «Сохранить в файл…» — можно перезаписать файл или дописать прототип в конец существующего.

### Вкладка «Meta-файл спрайтов (RSI)»
Укажите разрешение, лицензию и авторство, добавьте состояния (название, направления 1/4/8,
анимация: число кадров + задержка, либо свои задержки списком) и сохраните `meta.json` — его
остаётся положить в папку `.rsi`. Дополнительно:
* **«Состояния из PNG в папке…»** — создаёт состояния по именам файлов `*.png`;
* **«Открыть готовый meta.json…»** — загрузить существующий файл для правки.

## Как добавить компонент

Компоненты лежат в JSON-файлах: `data/components/` (встроенные) и **`custom/components/`**
(ваши; загружаются позже и **заменяют** встроенные с тем же именем). Пример —
`custom/components/_example.json.off` (уберите `.off` из имени). Затем в приложении нажмите **F5**.

```json
{
  "category": "Мои компоненты",
  "components": [
    {
      "name": "MyCustomComponent",
      "description": "Что делает компонент",
      "fields": [
        {"key": "someText",   "label": "Текст",  "type": "string", "required": true},
        {"key": "someNumber", "label": "Число",  "type": "float"},
        {"key": "mode",       "label": "Режим",  "type": "enum", "options": ["A", "B"]}
      ]
    }
  ]
}
```

Категорию можно задать на уровне файла или у отдельного компонента (`"category"`).
Порядок категорий в списке — по порядку файлов (поэтому встроенные файлы пронумерованы `01_…`).

## Как добавить тип прототипа

Файл JSON в `custom/prototype_types/` (один объект или список объектов):

```json
{
  "type": "myPrototype",
  "label": "MyPrototype — мой тип",
  "description": "Подсказка под выбором типа",
  "supports_components": false,
  "fields": [
    {"key": "id",   "label": "ID",   "type": "string", "required": true},
    {"key": "name", "label": "Имя",  "type": "string"}
  ]
}
```

`type` — то, что попадёт в строку `- type: …`; `supports_components: true` включает панель
компонентов (как у `entity`).

## Типы полей

| type | Что это | Результат в YAML |
|---|---|---|
| `string` / `text` | строка / многострочный текст | `key: значение` |
| `int` / `float` | число (проверяется) | `key: 1.5` |
| `bool` | «по умолчанию / true / false» | `key: true` |
| `enum` | выбор из `options` (`"editable": true` — можно вписать своё) | `key: Items` |
| `color` | цвет с палитрой | `key: "#FF8800"` |
| `vector2` | пара X, Y | `key: 1.5,2` |
| `list` | список значений (`item_type`: string/int/float) | `key:` + `- элементы` |
| `map` | пары «ключ — число/строка» (`value_type`) | `key:` + `ключ: значение` |
| `group` | вложенный объект (`fields`) | вложенные ключи |
| `objlist` | список объектов (`item_fields`, `item_label_key`) — как `layers` у `Sprite` | `- …` |

Общие ключи поля: `key` (обязателен), `label`, `required`, `help` (подсказка), `placeholder` (пример).
Незаполненные поля в YAML не попадают. Ключ `type` для полей зарезервирован.

Ошибки в JSON не ломают программу: проблемные записи пропускаются, а список проблем показывается при
запуске и при перезагрузке (F5).

## Важно про версии SS14

Набор полей встроенных компонентов отражает типичные названия из кода SS14, но движок и контент
меняются. Если у вашей сборки поле называется иначе — поправьте JSON (или переопределите компонент
в `custom/`). Сложные структуры, которых нет в списках, можно дописать в готовый YAML вручную.

## Структура проекта

```
main.py                    запуск
ss14pb/models.py           описания полей, компонентов, типов
ss14pb/registry.py         загрузка JSON (data/ + custom/)
ss14pb/yaml_emit.py        вывод YAML в стиле SS14
ss14pb/builder.py          сборка прототипа, запись файла
ss14pb/rsi.py              генерация meta.json
ss14pb/ui/                 интерфейс (tkinter)
data/                      встроенные компоненты и типы
custom/                    ваши компоненты и типы
tests/                     python -m unittest discover -s tests
```
